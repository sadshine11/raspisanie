# Расписание — приложение для iPhone

Приложение показывает расписание занятий ХТИ (филиал СФУ), при каждом запуске
сверяет его с официальным сайтом и показывает, что изменилось.

Группа по умолчанию — **56-1 (ХБ 26-01)**, доступны все 34 группы обоих семестров.

## Что умеет

- **Сегодня** — занятия текущего дня, подсветка идущей пары с полосой прогресса,
  карточка «следующая пара» с обратным отсчётом, номер учебной недели.
- **Неделя** — полная сетка с переключением между 1-й и 2-й неделей.
- **Изменения** — история отличий от прошлой проверки: заменённый предмет,
  другой кабинет, другой преподаватель, добавленные и убранные занятия.
- **Настройки** — выбор группы (с поиском), фильтр по подгруппе, ссылка на
  официальную страницу.
- Ссылки на курсы в Moodle СФУ открываются прямо из карточки занятия.
- Расписание кэшируется: без сети показывается последняя загруженная версия.

## Как это устроено

Бэкенда нет. Приложение само ходит на сайт расписания и разбирает HTML:

```
http://89.249.130.60:7085/viewer/edu-group-schedule?id_schedule=116&id_edu_group=3281
                    │
                    ▼
        ScheduleParser  (разбор разметки Yii2)
                    │
                    ▼
        ScheduleDiffer  (сравнение с сохранённым снимком)
                    │
                    ▼
            история изменений + экраны
```

Две особенности сайта, из-за которых разбор устроен именно так:

1. **Ячейки «пара» и «время» объединяются через `rowspan`.** У строки-продолжения
   меньше колонок, и наивный разбор молча терял такие занятия — на 34 группах
   это 49 потерянных занятий из 728.
2. **Название предмета может быть ссылкой и содержать запятые** —
   например, «Металлические конструкции, включая сварку». Поэтому ячейка режется
   по `<b>`-сегментам, а не по запятым.

Сайт работает по обычному HTTP (не HTTPS), поэтому в `Info.plist` ослаблена
политика App Transport Security. Приложение ставится по сертификату и не проходит
проверку App Store, так что на это ограничение можно не оглядываться.

Авторизация не нужна: страницы расписания открыты всем.

## Сборка

Собрать iOS-приложение можно только на macOS. Если у вас Windows, сборку делает
GitHub Actions на бесплатном macOS-раннере.

1. Создайте репозиторий на GitHub и отправьте туда код:

```bash
git add . && git commit -m "Приложение расписания" && git branch -M main
```

2. Привяжите репозиторий и запушьте:

```bash
git remote add origin https://github.com/ВАШ_ЛОГИН/raspisanie.git && git push -u origin main
```

3. Дождитесь workflow **«Сборка IPA»** во вкладке Actions. Он прогоняет тесты
   на симуляторе, собирает неподписанный `Raspisanie.ipa` и кладёт его в
   релиз `latest` — с постоянной ссылкой для скачивания с телефона.

Тег нужен только для именованной версии, на каждый день он не требуется:

```bash
git tag v1.0 && git push origin v1.0
```

**Репозиторий должен быть публичным.** Прямая ссылка на файл из релиза работает
без авторизации только у публичных репозиториев — иначе подписывающее приложение
на телефоне не сможет его скачать. Секретов в коде нет: расписание и так открыто
всем, а сертификат хранится только у вас на устройстве.

## Установка на iPhone

`.ipa` собирается **без подписи** — это сделано намеренно: подпись ставится
вашим корпоративным сертификатом `.p12` прямо на телефоне, компьютер не нужен.
Ключ никуда не выгружается и в репозиторий не попадает.

После первой же сборки ветки `main` появляется постоянная ссылка на файл —
она не меняется от сборки к сборке:

```
https://github.com/ВАШ_ЛОГИН/raspisanie/releases/download/latest/Raspisanie.ipa
```

Ссылка идёт на тег `latest`, который перезаписывается каждой сборкой ветки
`main`. Именно `/releases/download/latest/`, а не `/releases/latest/download/` —
второй адрес пропускает пред-релизы и здесь не сработает.

Порядок действий:

1. Один раз импортируйте в подписывающее приложение (ESign или аналог) свой
   сертификат `.p12` и provisioning profile.
2. Вставьте туда ссылку выше — файл скачается сам. Либо скачайте `.ipa` через
   Safari и откройте его в подписывающем приложении.
3. Подпишите и установите.
4. При первом запуске: **Настройки → Основные → VPN и управление устройством** →
   доверить профиль разработчика.

Для обновления после новой сборки повторяются только шаги 2–3 — ссылка та же.

**Bundle ID — `ru.eleqq.raspisanie`.** При переподписи оставляйте его прежним:
тогда сохранятся выбранная группа, кэш расписания и история изменений. Если
подписывающее приложение поменяет bundle ID, приложение встанет как новое
и настройки обнулятся.

Приложению не нужны никакие особые разрешения — ни push-уведомлений, ни общих
контейнеров, ни доступа к связке ключей. При переподписи ломаться нечему.

Минимальная версия iOS — 16.0.

Если корпоративный сертификат отзовут (Apple это периодически делает),
приложение перестанет запускаться. Лечится переподписью новым сертификатом,
пересобирать ничего не нужно — `.ipa` тот же.

## Если расписание перестало загружаться

Скорее всего на сайте переделали вёрстку. Проверить можно, не открывая Xcode:

```bash
node tools/canary.js 116 3281
```

Скрипт скачает живую страницу и скажет, что именно перестало разбираться.
Он же запускается в GitHub Actions каждый день (workflow «Проверка сайта
расписания») — если сайт недоступен снаружи, проверка помечается как пропущенная,
а не как поломка.

`tools/parse.js` — эталонная реализация разбора на JavaScript. Логика в
`Sources/Core/ScheduleParser.swift` повторяет её один в один, так что удобно
сначала чинить парсер здесь, а потом переносить правку в Swift.

## Структура

```
Sources/
  App/         точка входа
  Model/       Schedule, Lesson, диф расписаний
  Core/        парсер, сетевой клиент, хранилище, календарь учебных недель
  UI/          экраны и оформление
Tests/         тесты парсера, дифа и календаря + сохранённые страницы сайта
tools/         эталонный парсер на JS и ежедневная проверка сайта
```

## Тесты

Тесты — единственный способ проверить Swift-код, если под рукой нет Mac,
поэтому они прогоняются в CI до сборки `.ipa`. Проверяются:

- разбор реальных страниц двух групп с точным числом занятий (34 и 8);
- восстановление занятий из строк с `rowspan`;
- названия предметов со ссылками на курсы и запятыми внутри;
- сравнение расписаний: замена в слоте — одно изменение, а не «убрали + добавили»;
- чередование учебных недель, фильтр подгрупп, определение текущей пары.
